# Evals

The point of this directory: prove retrieval works, with numbers a reviewer can
reproduce. A model grading its own output is not evidence; a human labeled the
right answers.

## Files

- `queries.txt` — 50 candidate queries, written before any results were seen.
- `labels.json` — the eval set: query + the postings a human marked relevant.
  **This is the file that matters.** Committed, so a reviewer can see it grow.
- `labels.smoke.json` — mechanically generated by a title-match rule. It exists
  only to check the harness plumbing. It is **not** a measurement of the system:
  labels built from title strings structurally favour lexical search.

## How to label

```bash
make label          # walks each unlabeled query, asks y/N per top-10 hit
make eval           # hit@5, hit@10, MRR per retrieval mode
```

Rules that keep the labels honest:

1. Judge by **would this person plausibly do this job**, not by keyword overlap.
2. Mark every posting that qualifies in the top 10 — not just the ones you like.
3. A query with no relevant posting stays empty. It is not a broken question; it
   is a real "nothing here fits" case your system should also handle.
4. Never edit a label after seeing the score. If a label was wrong, note it in
   the commit message and fix it, don't quietly retune.

## What the numbers mean

- **hit@5** — of the labeled queries, how many had at least one correct posting in
  the top 5. This is what a user experiences.
- **MRR** — 1/rank of the first correct posting, averaged. Rewards putting the
  right answer first rather than merely somewhere on page one.
